# ThreatScope

**One Digit, Different Decisions** — research artifact

**Quantization-dependent example sensitivity in structured cyber-threat intelligence relevance selection**

Research artifact for the manuscript in preparation for *Computers & Security*.
Repository: <https://github.com/urazy1982/ThreatScope> (release v1.0.0).

ThreatScope was developed under the working name *ThreatStudy*. Frozen identifiers
(selection salts, protocol IDs, some file and folder names) keep that name, because
changing them would change the recorded hashes.
Author: Uraz Yavanoğlu, Department of Computer Engineering, Gazi University, Ankara, Türkiye
([ORCID 0000-0001-8358-8150](https://orcid.org/0000-0001-8358-8150)).

## What the study asks

Instruction-tuned LLMs used to select relevant sentences from cyber-threat
intelligence (CTI) reports are given a structured output template such as
`{"relevant":[k]}`. The digit `k` is only a formatting example. We ask whether
4-bit NF4 deployment makes a model's *decisions* depend more on that one digit
than the same model in BF16.

Design: 9 publishers × 8 APT reports × 2 eight-sentence windows = 144 windows;
3 models (Qwen2.5-3B-Instruct, Llama-3.2-3B-Instruct, Mistral-7B-Instruct-v0.3)
× {BF16, NF4} × 8 example indices; three output procedures:

| Arm | Output procedure | Calls |
|---|---|---:|
| A (v2.1.6) | free generation of a JSON index list | 6,912 |
| B (v2.2.1) | grammar-constrained canonical JSON (256 legal subsets) | 6,912 |
| C (v2.2.1) | forced single choice by teacher-forced candidate likelihood | 6,912 |
| replay | 432 archived Arm A calls re-run in the v2.2.1 environment | 432 |

Endpoint: publisher-equal, report-equal NF4−BF16 difference of the
example-index interaction (on-example minus off-example selection probability).
Primary test: exact two-sided publisher sign-flip test (2^9 sign patterns), Holm
correction over the three models within each arm.

## Main results (NF4 − BF16, percentage points)

| Model | A: free | B: constrained JSON | C: single-choice likelihood |
|---|---:|---:|---:|
| Qwen2.5-3B | +11.36 (Holm p = 0.012) | +11.42 (0.012) | +0.30 (0.785) |
| Llama-3.2-3B | +4.97 (0.016) | +7.16 (0.012) | +6.94 (0.012) |
| Mistral-7B | +6.01 (0.016) | +4.85 (0.012) | +2.48 (0.031) |

Constraining the output format does not remove the effect. Under forced
single-choice scoring it remains for Llama and Mistral but is not detectable for
Qwen. Arm C also changes the instruction and inference procedure, so this is
**not** evidence that output cardinality mediates the Qwen effect. The 432 replay
outputs are byte-identical to the archived Arm A outputs.

## Relevance labels

- `annotation/human_labels/`: labels from two cybersecurity professionals on a
  288-item subset with their jointly adjudicated label (primary), plus the AI labels
  for the same items, the three-rater majority and the pre-adjudication agreement
  label; results in `results/human_labels/`.
- `annotation/ai_labels/`: AI-generated labels for all 1,152 targets (exploratory).

See `annotation/README.md` for the procedure, deviations and commands.

## Exploratory AI-generated reference labels

`annotation/ai_labels/` contains relevance labels for all 1,152 targets produced
by one LLM (claude-fable-5-2, single pass) after all results were known. They are
**not human judgements and not ground truth**; see `annotation/README.md`.
`python3 annotation/analyze_ai_labels.py` reproduces the exploratory quality
analysis (`results/ai_labels/`).

## Reproduce every statistic (≈15 s, Python ≥ 3.10, standard library only)

```bash
python3 reproduce/reproduce_all.py --out results_rerun
```

This verifies all file hashes, recomputes Arm A from 6,912 checkpoint records,
runs the independent auditor over 14,256 Arm B/C/replay records, and checks the
outputs against `results/` byte for byte. Individual steps:

```bash
python3 reproduce/verify_release.py
python3 reproduce/recompute_armA.py --out results_rerun/armA
python3 reproduce/run_audit_v221.py  --out results_rerun/audit_v221
```

## Data and copyright

Reports come from the research-use-only
[CZLi/apt-reports](https://huggingface.co/datasets/CZLi/apt-reports) collection
(gathered with [CTI-Crawler](https://github.com/peng-gao-lab/cti-crawler)); the
reports remain the copyright of their publishers. **No report text is
redistributed here.** Every window and sentence is identified by SHA-256 so a
re-acquired copy can be verified exactly. See [DATA_STATEMENT.md](DATA_STATEMENT.md).

## Re-running model inference

Inference needs the original window texts, pinned model revisions, and an
NVIDIA GPU with ≥ 32 GB memory (the study used an RTX 5090, CUDA 12.8,
torch 2.10.0, transformers 5.22.2, bitsandbytes 0.50.2). Restore the
text-bearing reference archive with `reproduce/restore_reference_archive.py`,
then follow `src/v221_mechanism/README_v221.md`. The frozen code refuses to run
if any frozen file or the reference archive hash differs.

## CPU test suites

```bash
cd src/v221_mechanism && python3 -m pytest -q   # 89 tests without torch; full suite needs torch + tokenizers
cd src/v216_inference && python3 -m pytest -q   # 73 tests without torch/huggingface_hub
```

The text-dependent v2.2.1 tests need the restored reference archive (see above).

## Limitations, stated up front

- Decision sensitivity is measured, not relevance accuracy; the human-labelled
  subset (`annotation/`) adds a bounded accuracy view.
- Nine publisher clusters; bootstrap intervals are descriptive.
- Arms B and C were designed after Arm A results were known; they were frozen by a
  local SHA-256 amendment, not an external preregistration.
- Original report text, model weights and the 10.7 GB source archive are not included.
